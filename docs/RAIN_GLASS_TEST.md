动态水雾玻璃雨滴，雨滴汇聚水珠滑落shader，多层的shader叠加的不是单一的，不同雨滴打上去的效果等等，水雾一层shader，不同雨滴shader，水珠滑落shader，不同雨滴要随机不规则，水雾是固定的，雨滴不规则打在玻璃上，水珠从不规则滑动，总体有一定透明度，雨滴要有法线，雨滴有落上去消逝等等特效而不是单纯存在在玻璃上，水珠少量，滑落符合物理规则路径上碰到水珠会加速，也会改道，从高到低，还有可能分叉，等等形态，雨滴大小较为小并且大小要随机，水珠滑落是轨迹会存在一段时间但是不会乱窜，轨迹也应该细，水滴应该是不规则形状的并且中心清晰两边逐渐和背景相融，水雾不是不规则的雾，是指在玻璃上凝结的一层细密小水滴别用水滴表现形式用均匀的雾 的表现形式，这个shader存在透明度，水滴滑落后轨迹在一定时间内消逝，雨滴打上去的效果雨滴位置不动一段时间消逝

## 修复前的实测

- 页面模型：`deepseek-flash`。26 个节点，2 次模型调用，文档 hash `09cf51e5`。
- Agent 返回 `clean=true`；真实 WebGL 驱动却报告第 353 行 `hi` 重定义、第 354 行 `nrm` 重定义。
- 原因：雨滴、滑落两个 custom_glsl 节点的局部变量被拼在同一函数作用域中。
- 雾层使用 FBM，不符合均匀雾面的要求；滑落路径的横向噪声依赖连续时间，残留路径也会横向漂移。
- 对 iChannel0 采样不能证明真实背景折射；末尾强制 alpha 为 1，不满足透明要求。

## 已修复的通用链路

- 自定义节点作用域隔离，同时支持 WGSL 对裸语句块内声明和循环的转换。
- 在线补丁允许设置透明与反馈；严格检查布尔值。
- 微调执行用户请求，空修改和拒绝的补丁不再被当成完成。
- HTTP 补丁解析以当前文档为初始状态；此前对已有 custom_glsl 的 set_body 被误判为未知节点并丢弃，导致模型说明已修改、实际只添加了未使用的参数。已用模拟 HTTP 响应覆盖真实解析与应用链路。
- 模型上下文包含自定义代码、完整规格、透明与反馈设置。
- 起草后的源码需求复核；浏览器的真实 GLSL 片元编译错误回流。
- 提示词解释独立层、稳定事件随机数、寿命、向下路径、轨迹年龄衰减、法线和透明限制。
- 帧号从 0 开始，倒退时间时清除反馈，避免负时间步长污染积累。

## 验收边界

材质预览的 `seamless`（接缝融合）默认开启：四个平移副本交叉淡入。
UV 模式每片元 4 次采样，三平面模式 12 次；关闭时分别为 1/3 次。
它会改变图案，大尺度特征可能出现重影；细密噪声通常不明显。UV 重复次数取整，
导出 shader 不携带这项预览处理。已经周期连续的图案可关闭以减少成本和重影。

`transparent` 产物现在记录 straight-alpha 宿主混合、深度写入和排序要求；ShaderLab
直接生成 Transparent Queue/RenderType、Blend 和 ZWrite Off。反馈状态 pass 应关闭
混合，只在最终呈现阶段混合；这些说明不代表已在 Unity/UE/Metal 中运行验收。

源码复核不是视觉评测，GLSL 编译不是六种目标引擎的运行验收。
当前没有碰撞驱动的水滴质量/速度模拟、多状态缓冲或真实场景颜色输入。
碰撞合并、加速、改道和分裂若仅由解析轨迹模拟，必须作为近似明确列出。
效果需用连续帧观察，不能只用一张截图证明水滴生命周期和残留消退。
